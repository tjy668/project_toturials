
# 《节奏康复》移动端游戏视觉与交互设计规范 v1.0

**适用范围**：2026 复客松首版移动 Web 体验  
**设计对象**：用户端首页、准备/校准、动作教学、正式训练、暂停/恢复、结果、历史、绑定，以及治疗师端的品牌基础规范  
**实现环境**：iPhone Safari、Android Chrome/系统浏览器；React + TypeScript + Vite；MediaPipe Hand Landmarker；竖屏优先  
**视觉交付原则**：所有视觉方案必须能够通过 CSS、SVG、普通 DOM、短视频与短音效实现；不依赖 3D 游戏引擎，不要求持续 Canvas 粒子系统。

---

# 1. 产品体验定位

## 1.1 核心认知顺序

现场普通观众看到产品后，希望形成以下认知：

**第一层：这是一个我愿意试一试的轻量游戏。**

↓

**第二层：原来它是通过手部动作来完成训练的。**

↓

**第三层：系统真的能够识别我的动作与节奏。**

因此不以“医疗设备”作为第一视觉印象，也不以“计算机视觉 Demo”作为第一视觉印象。

PRD 已经将首版定位为面向复客松评委和普通观众的实际体验，核心展示能力是“摄像头识别手部动作 + 节奏判定 + 有趣的视听内容”；同时明确游戏成绩不表示康复疗效。fileciteturn2file8L256-L264

## 1.2 品牌人格

核心人格：

**轻 / 净 / 柔 / 准**

对应含义：

| 关键词 | 设计含义 |
|---|---|
| 轻 | 信息密度低，不像医疗仪表盘 |
| 净 | 大面积留白与明确层级，不堆视觉装饰 |
| 柔 | Miss、丢手、暂停不产生惩罚感 |
| 准 | 动作、节拍、识别状态必须非常清楚 |

品牌语气：

**轻快、清晰、鼓励、可信。**

明确避免：

- 医疗化
- 电竞化
- 儿童化
- 炫技式科技感
- 高压竞争感
- “成绩越高越健康”的暗示

## 1.3 美学方向

最终母视觉：

> **轻量音游的交互骨架 + 极简治愈的视觉气质。**

推荐定义为：

> **安静、有节奏的治愈。**

不是奶油系可爱 App，也不是霓虹音游。

设计关键词：

**Warm Minimalism / Soft Rhythm / Quiet Feedback**

---

# 2. 总体视觉原则

整个产品遵循一条核心原则：

> **平时静，状态变化时才动。**

视觉能量只在以下时刻出现：

- 动作即将切换
- 目标节拍到来
- Perfect / Good 判定
- 手部重新被识别
- 训练完成

其余时间保持安静。

游戏感主要来自：

**动画触发时机 + 音乐同步 + 实时反馈**

而不是：

大量粒子、震屏、霓虹、常驻动画。

↓

# 4. 首页与主题选择

## 4.1 页面目标

首页只回答三个问题：

1. 这是什么？
2. 我可以玩什么？
3. 怎么开始？

不在首页解释算法和复杂康复背景。

## 4.2 信息顺序

顶部：

**品牌名称 / 简短一句话**

建议：

> 跟着音乐动动手

副文案：

> 摄像头会自动识别你的动作与节奏

中部：

三个主题卡。

底部：

- 我的记录
- 绑定治疗师

## 4.3 主题卡结构

每张卡：

- 主题 Poster
- 主题名称
- `约 90 秒`
- 简短氛围描述
- 开始按钮

不展示：

- 难度星级
- 排名
- Combo
- 高分纪录

三个主题共用相同动作和判定逻辑，因此卡片不暗示不同康复强度。

# 5. 准备与摄像头校准

这里需要和正式训练明确区分。

## 5.1 摄像头显示规则

### 准备阶段

**显示真实镜像摄像头画面。**

目的：

- 判断手机位置
- 判断手是否完整入镜
- 调整距离
- 调整光线

### 正式训练阶段

**不显示真实摄像头画面。**

摄像头继续后台工作，但 UI 只呈现抽象化的“手部感知轮廓”。

这是本轮设计讨论形成的明确变更。

现有 PRD 和前端架构仍写有“训练页角落摄像头预览”，后续需要同步修改文档。fileciteturn1file1L73-L81 fileciteturn1file0L45-L53

# 6. 初始手部校准

## 6.1 默认状态

屏幕中下方出现一个固定的手部引导区域。

形式：

- 柔和虚线
- 无真实手部照片
- 无复杂网格
- 无科技扫描线

提示：

> 把手放进这里

## 6.2 校准成功

检测稳定后：

虚线颜色从浅灰棕进入 Cocoa / Theme Accent。

同时：

- 轮廓轻微收紧
- 出现短暂 ✓
- 文案：“已准备”

然后自动进入动作教学。

## 6.3 校准失败

根据问题区分：

**手太靠边**

> 稍微往中间一点

**距离不合适**

> 调整一下距离

**没有识别到**

> 把一只手完整放进画面

不显示：

“Tracking Error”

“置信度不足”

“识别失败”

# 7. 动作教学系统

采用用户提出的 **Keep 式单动作教学逻辑**。

这里借鉴的是其信息组织方式，不是复制 Keep 的具体 UI 视觉。

## 7.1 基础模型

一个动作一屏。

每屏包括：

- 动作示范
- 动作名称
- 一句动作提示
- 用户尝试区域
- 当前教学进度
- “跳过示范”

三个动作依次为：

**手指伸直 → 钩拳 → 握拳**

## 7.2 “跳过”的定义

可以：

> **跳过动作教学内容**

不能：

> **跳过摄像头识别确认**

技术方案要求正式训练前确认当前环境能够可靠区分目标姿态，因此即使用户已经熟悉动作，也需要完成基础识别确认。fileciteturn1file6L249-L263

## 7.3 动作示范素材

优先：

- 真人手部短视频
- 专业审核后的动作图

不使用未经检查的 AI 手部画面直接作为动作标准。PRD 和技术路径已经明确要求动作示范与生成式情境视频分开制作。fileciteturn1file9L356-L368

建议每个动作：

**2–4 秒循环短片**

无须解说音轨。

播放逻辑：

起始姿势  
→ 目标姿势  
→ 短暂停留  
→ 回到起始状态

---

# 8. 正式训练页——核心页面结构

这是整个产品视觉等级最高的页面。

## 8.1 核心原则

> **90 秒情境视频是唯一主视觉。**

UI 不能和视频形成多个竞争中心。

技术路径明确规定三套主题均输出带音乐的连续 `training.mp4`，视频同时承担正式媒体内容和主时间轴。fileciteturn2file2L68-L74

## 8.2 图层结构

推荐固定 Z 轴：

| 层级 | 内容 |
|---|---|
| Z0 | Theme Training Video |
| Z10 | Hand Aura 手部感知轮廓 |
| Z20 | Action Cue / Hold Progress |
| Z30 | Perfect / Good / Miss |
| Z40 | Training HUD |
| Z50 | Pause / Recovery / Countdown Overlay |

## 8.3 视频

视频建议：

```text
position: absolute
inset: 0
width: 100%
height: 100%
object-fit: cover
```

不使用原生 controls。

由于技术方案采用 540×960 竖屏素材，而不同手机纵横比不同，视频制作时必须预留安全构图区。

### Video Safe Zone

关键角色、关键动作、剧情重点：

建议始终落在：

**中央约 80% 宽度区域**

避免最左右两侧承载关键信息。

顶部和底部需要预留 UI 安全空间。

技术文档已经要求素材顶部为评分/暂停预留区域，底部为动作与保持信息预留区域。fileciteturn2file3L86-L98

# 9. Training HUD

常驻 HUD 必须极简。

## 9.1 顶部左侧

剩余时间：

```text
01:24
```

不显示进度百分比。

## 9.2 顶部右侧

只常驻：

**Pause**

建议圆形线性图标按钮。

退出功能进入 Pause Overlay 后提供。

这样减少训练页常驻按钮数量，同时仍然保留退出能力。

## 9.3 HUD 表面

建议：

暖白半透明 Surface：

```css
rgba(255,253,252,.88)
```

必要时使用轻阴影。

禁止重度 `backdrop-filter: blur()`。

---

# 10. 动作提示 Action Cue

正式训练中**不常驻动作示范**。

教学负责“教会”。

训练负责“提醒”。

每个任务按照现有 6 秒协议工作；当前技术方案建议目标节拍位于任务开始后的第 2 秒。fileciteturn0file1L83-L120

推荐视觉时间轴：

```text
0.0s   Action Cue 出现
1.5s   Cue 开始轻微呼吸
2.0s   Target Beat
2.0–2.3s Cue 淡出
之后   仅显示跟手轮廓与保持进度
```

Cue 内容：

- 极简动作 SVG / PNG
- 动作名称

例如：

```text
[手势图]

钩拳
```

不使用第二个真人视频持续叠在情境视频上。

# 11. Hand Aura 手部感知轮廓

这是首版视觉系统中最重要的原创 UI 模块之一。

## 11.1 定义

Hand Aura ≠ 摄像头预览。

Hand Aura ≠ 精准人体分割。

Hand Aura 是：

> **MediaPipe 手部关键点驱动的抽象视觉反馈。**

技术层能够获得 21 个 hand landmarks，但当前方案并不包含实时手部像素分割，因此 UI 不应该假装生成精准真实手边缘。fileciteturn1file6L259-L263

## 11.2 外形

推荐：

- 柔性封闭包络
- 虚线或点划线
- 圆角端点
- 手掌宽度附近适当留白
- 不画 21 个骨骼节点
- 不显示人体扫描网格

第一版不要求精确描绘五指轮廓。

## 11.3 空间行为

### 校准状态

固定锚点。

### 正式训练

解除锚点。

轮廓：

- 跟随手部中心
- 跟随总体尺度
- 可轻微跟随旋转
- 不跟随检测抖动

推荐视觉平滑延迟：

**约 120–180ms**

这是视觉滤波，不影响评分时间戳。

评分仍由 TrainingEngine 与捕获时间决定，前端视觉不得反过来影响判定。

## 11.4 安全活动区

轮廓不允许完全跑出屏幕。

接近边缘：

- Aura 轻微变淡
- 出现方向提示

例如：

> 稍微往中间一点

# 12. Hold Progress 保持进度

为了减少底部常驻 UI，我推荐将保持进度直接与 Hand Aura 绑定。

形式：

**Aura 外围细弧 / 细环**

动作正确并持续保持：

环逐渐完成。

姿势中断：

环柔和归零。

不要使用：

- 大型横向游戏血条
- 百分比数字
- 红色失败进度

动作完成与节奏判定属于两个独立指标，因此 Hold Progress 必须和 Perfect/Good/Miss 视觉上解耦。PRD 已明确：用户可以 Perfect 但保持未完成，也可以节奏 Miss 但最终动作完成。fileciteturn0file0L102-L114

---

# 13. Perfect / Good / Miss

核心情绪定义：

> **Perfect = 绽开**
>
> **Good = 回应**
>
> **Miss = 略过**

不采用：

绿色成功 / 黄色一般 / 红色失败。

## 13.1 Perfect

视觉：

- `Perfect`
- 短暂 Scale
- Hand Aura 瞬间增强
- 一圈完整扩散 Ring
- 少量主题化 SVG 点/形状

时长：

**约 560ms**

声音：

短、亮、清脆。

## 13.2 Good

视觉：

- `Good`
- 小幅波纹
- Aura 短暂增亮

时长：

**约 420ms**

不产生大量装饰。

## 13.3 Miss

视觉：

- `Miss`
- 扩散环未完成即淡出
- 弱灰棕

辅助文案：

> 下一拍继续

禁止：

- 红闪
- ×
- 屏幕震动
- 错误警报
- 失败音
- 视频角色失望反应

---

# 14. 判定反馈位置

Perfect / Good / Miss 不固定在屏幕正中央。

推荐：

> **跟随 Hand Aura，但不覆盖 Hand Aura。**

默认：

手部轮廓上方约 24–40 px。

如接近顶部，则翻转至下方。

目的：

让用户产生明确因果：

**“这是我的动作产生的反馈。”**

而不是：

“屏幕中央弹出一个系统通知。”

---

# 15. Combo

**首版完全取消 Combo 系统。**

不设计：

- Combo Counter
- 连击进度
- Combo 中断
- Combo 成绩
- Combo 粒子

理由：

当前动作任务本身不属于高难度音游操作，Combo 不增加训练信息，反而增加视觉与前端状态复杂度。

---

# 16. 丢手 Hand Lost

丢手不属于用户失败。

技术规则已经规定持续无法跟踪时暂停，不能直接结算为 Miss。fileciteturn2file2L58-L66

视觉过程：

```text
TRACKED
↓
ADJUST
↓
Aura 变淡 / 断裂
↓
LOST
↓
Aura 消散
↓
暂停
```

## 16.1 短暂不稳定

文案：

> 让手保持在画面里

## 16.2 确认丢失

视频暂停。

背景：

轻微降低亮度。

中部：

**没看到手**

辅助：

**把手放回画面中**

不要使用错误 Icon。

---

# 17. 找回手部 Reacquisition

用户重新入镜：

```text
散点
↓
重新聚合
↓
Hand Aura 成形
↓
“找到了”
↓
3
2
1
↓
重播当前动作
```

文案：

> 重新开始这个动作

技术方案规定恢复时重新进入当前受影响任务，而不是从被中断的节拍中间继续。fileciteturn2file2L58-L66

---

# 18. 主动暂停

主动暂停与 Hand Lost 必须视觉区分。

主动暂停：

- 视频停住
- 暖色半透明 Scrim
- 不播放“消散”动画

中央操作：

**继续训练**

次级操作：

**退出训练**

辅助说明：

> 退出后本次不会计入打卡

禁止使用：

“放弃训练”

“挑战失败”

---

# 19. 会话状态到 UI 的映射

当前核心状态机：

`PREPARING → TUTORIAL → READY → COUNTDOWN → PLAYING ↔ PAUSED → COMPLETED / ABORTED`。fileciteturn2file2L58-L66

UI 映射：

| Engine 状态 | 主要 UI |
|---|---|
| PREPARING | 摄像头准备 / Loading |
| TUTORIAL | 单动作教学 |
| READY | “准备完成” |
| COUNTDOWN | 3 / 2 / 1 |
| PLAYING | 视频 + Aura + Action Cue |
| PAUSED / HAND_LOST | Recovery Overlay |
| PAUSED / USER | Pause Overlay |
| PAUSED / MEDIA | “训练内容暂停加载” |
| PAUSED / BACKGROUND | 返回页面后的恢复提示 |
| COMPLETED | Result Page |
| ABORTED | 未完成 Result |

UI 不自行复制评分逻辑，所有业务状态必须由 TrainingEngine 提供；前端架构已经明确这一职责边界。fileciteturn2file4L120-L138

# 20. 结果页

结果页第一层不是“分数”。

第一层是：

# 训练完成

或者：

# 完成今天的训练

下面再展示结果。

## 20.1 第一指标

**动作完成**

例如：

```text
13 / 15
87%
```

## 20.2 第二指标

**节奏表现**

例如：

```text
82
```

不要命名为：

“康复分”

“健康分”

“恢复指数”

## 20.3 判定分布

展示：

Perfect  
Good  
Miss

但不强调排名。

## 20.4 其他信息

- 有效训练时间
- 打卡状态
- 本机保存状态
- 同步状态

## 20.5 CTA

主操作：

**再练一次**

次级：

**查看记录**

再次级：

**返回首页**

低分不影响“训练完成”的主标题。

# 21. 三主题设计系统

三个主题不是三个产品。

结构完全相同。

## 21.1 不允许变化

以下内容固定：

- 页面布局
- 字体
- 字号层级
- 图标
- 按钮位置
- Training HUD
- Action Cue
- Hand Aura 行为
- Perfect / Good / Miss 逻辑
- Pause / Lost Hand 行为
- 结果页结构
- 动画时间
- 交互规则

## 21.2 可变化范围

允许主题化：

- training.mp4
- poster
- 音乐
- accent color
- accent-soft
- highlight
- Perfect SVG
- Perfect / Good 音效
- 少量氛围文案

推荐主题感来源比例：

**70% 视频与音乐**

**20% 色彩与反馈装饰**

# 28. 动效时间 Token

```text
motion-fast       160ms
motion-normal     240ms
motion-feedback   420ms
motion-emphasis   560ms
```

缓动：

进入：

`ease-out`

退出：

`ease-in`

禁止：

- 全屏震动
- 持续旋转
- 大幅 Bounce
- 视差
- 长时间漂浮粒子
- 大面积实时 Blur

# 48. 最终视觉设计判断标准

任何新设计加入之前，都问四个问题：

**1. 它是不是帮助用户理解现在该做什么？**

**2. 它是不是帮助用户理解系统有没有识别自己？**

**3. 它是不是增强节奏反馈，而没有遮挡视频？**

**4. 如果删掉它，体验是否仍然完整？**

如果第四题答案是：

> “删掉也没区别。”

那么它大概率属于装饰，可以不做。

最终产品应该表现为：

> **视频负责世界，音乐负责节奏，手部轮廓负责连接用户，UI 负责告诉用户下一步怎么做，反馈负责让动作有回应。**

这五者的职责不能混淆。

# 49. 一句话设计定义

**《节奏康复》是一套以沉浸式情境视频为主舞台、以实时手部识别为交互入口、以极简节奏反馈建立游戏感的移动端训练体验；视觉上采用暖米白、可可棕与低饱和主题色，通过“点—线—环—扩散”的统一语言，在保证动作识别清晰度的前提下形成安静、柔和而有反馈感的游戏体验。**
