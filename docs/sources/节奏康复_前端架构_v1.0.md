# 节奏康复：前端架构 v1.0

版本：2026-09-11｜读者：前端负责人｜目标：9 月 13 日下午可演示的手机网页

这份文档用于单独开启前端开发讨论。它把前端负责的页面、模块、状态和外部接口固定下来，使前端可以先用开发适配器并行搭建，之后无缝换成真实识别与云端实现。

## 1. 前端目标和边界

前端交付同一个响应式 Web 应用，包含用户端和治疗师端。用户扫码进入后完成主题选择、摄像头告知、取景校准、90 秒训练、结果与本机历史；绑定治疗师后同步记录。治疗师登录后查看已绑定用户的汇总和训练记录。

前端负责页面流、交互、可访问性、媒体播放展示、状态呈现、本机历史 UI、同步状态和错误恢复。识别算法、评分规则、Supabase 权限由 B 提供模块；素材由 A 按 manifest 提供。前端不得从关键点重新计算手型，也不得在组件中复制一套判分公式。

首版手机竖屏优先，最低验证宽度 360px；桌面端提供可读布局，主要用于治疗师查看。支持范围以实际验证的 iPhone Safari 和安卓 Chrome 版本为准。

## 2. 技术基线

| 项目 | 选择 |
| --- | --- |
| 构建 | Vite + React + TypeScript，启用 `strict` |
| 路由 | React Router；页面懒加载；静态托管需 SPA fallback |
| 样式 | 普通 CSS Modules 或一个全局 token 文件；不要在两天内引入复杂设计系统 |
| 服务端状态 | TanStack Query，仅处理绑定、上传和治疗师查询；若尚未安装，可用薄 service + 明确 loading/error 状态 |
| 本机记录 | 通过 B 提供的 `SessionRepository`；底层 IndexedDB，不让页面直接操作数据库 |
| 业务状态 | 训练会话由 B 的 `TrainingEngine` 状态机管理；React 订阅低频快照 |
| 高频视觉 | `requestAnimationFrame` + CSS transform/opacity；不把 10–15 Hz 的每帧事件写入全局 React state |
| 测试 | Vitest + React Testing Library；关键移动端流程另做真机手测 |

如果工程已有可工作的同类依赖，保留现状，不为一致性重搭。首版不引入 Redux、微前端、SSR、Canvas 游戏引擎或 UI 大组件库。

## 3. 路由和页面

```text
/
├─ /                    首页与三个主题
├─ /prepare/:themeId    摄像头告知、左右手、取景、动作教学与校准
├─ /train/:themeId      正式训练
├─ /result/:sessionId   本次结果
├─ /history             本机历史
├─ /binding             治疗师邀请码与绑定状态
└─ /therapist
   ├─ /login            治疗师登录
   ├─ /patients         绑定用户列表
   └─ /patients/:id     用户训练详情
```

### 首页 `/`

- 一句话说明“跟随音乐完成手部动作，摄像头自动记录”。
- 三个主题卡：封面、标题、90 秒、动作组相同的说明。
- “我的记录”和“绑定治疗师”入口。
- 首次加载不预加载三段视频；进入准备页后只加载所选主题。

### 准备页 `/prepare/:themeId`

依次使用一个页面内的步骤器，避免多层路由：

1. 摄像头使用告知：匿名体验、不保存视频画面、记录默认保存在本机，绑定后同步给确认的治疗师；“继续并开启摄像头”。
2. 选择左手/右手；提示固定手机、光线充足、单手入镜、使用手机扬声器。
3. 取景检查：镜像预览、手部安全框、`未检测到 / 调整距离 / 已准备`。
4. 三动作教学：示范图、动作名称、保持进度；每种动作通过后进入下一步。
5. 预加载所选 MP4 与 manifest；准备完成后显示“开始训练”。

摄像头权限被拒绝时显示系统设置说明与重试；模型或素材失败时显示单项重试。不能用“跳过校准并模拟成绩”作为用户入口。

### 训练页 `/train/:themeId`

2026-09-12 按[移动端视觉与交互设计规范](./节奏康复_移动端视觉与交互设计规范_v1.0.md)更新。主画面图层固定：

1. Z0 情境视频 `<video>`：含音乐，是唯一播放主时钟。
2. Z10 Hand Aura：后台手部识别驱动的抽象包络；正式训练隐藏原始摄像头画面。
3. Z20 Action Cue / Hold Ring：节拍前短暂显示动作提示，保持进度附着于 Aura。
4. Z30 Perfect/Good/Miss：跟随 Aura，避免覆盖它；靠近顶部时移至下方。
5. Z40 Training HUD：左侧剩余时间，右侧只常驻暂停；退出放入暂停层。
6. Z50 倒数、暂停与恢复层。准备/校准仍显示真实镜像摄像头预览。

进入页面不能自动开跑。模型、摄像头、媒体和 manifest 全部 ready 后，用户点击“开始”，倒数 3 秒再播放。不要显示可拖动原生进度条，不提供倍速。

### 结果页 `/result/:sessionId`

- 完整训练：打卡成功、动作完成数/15、动作完成率、节奏分、Perfect/Good/Miss、有效时长。
- 未完成：明确“本次未完成，不计打卡”，仍展示已完成结果。
- 同步状态：仅本机、同步中、已同步、待重试；本机成功与云端成功分开表达。
- 操作：再练一次、返回首页、查看历史。低分不阻止打卡，也不输出康复效果判断。

### 本机历史 `/history`

按日期倒序展示；完整和未完成均保留。同日多次训练均列出，顶部打卡日历按“当日至少一次 completed”计算。空状态引导去训练；读取失败提供重试和清理损坏记录的安全路径。

### 绑定页 `/binding`

- 未绑定：昵称、邀请码、查询按钮。
- 查询成功：显示治疗师名称、分享范围“当前浏览器身份下已有及未来的训练汇总，包含未完成记录”，再由用户点击确认。
- 已绑定：治疗师名称、绑定时间、同步状态和解除入口。
- 网络失败不能显示绑定成功；输入错误不泄露邀请码列表。

后端可把邀请码逻辑封装在一个服务函数中，但前端交互始终保留“预览 → 明确确认”两步。

### 治疗师端

登录页只服务预置账号。用户列表显示昵称、今日是否打卡、最后训练时间；详情显示日期、主题、完整状态、时长、动作完成率和节奏计数。显示最后刷新时间和手动刷新，不做诊断解释。

患者匿名会话和治疗师会话使用不同的 Supabase `storageKey` 或独立 client，避免同一浏览器登录治疗师时覆盖患者身份。

## 5. 与 B 的前端合同

### 核心类型

```ts
export type Pose = 'STRAIGHT' | 'HOOK' | 'FIST' | 'UNKNOWN';
export type TrackingQuality = 'GOOD' | 'ADJUST' | 'LOST';
export type Grade = 'PERFECT' | 'GOOD' | 'MISS';
export type SessionStatus =
  | 'PREPARING' | 'TUTORIAL' | 'READY' | 'COUNTDOWN'
  | 'PLAYING' | 'PAUSED' | 'COMPLETED' | 'ABORTED';

export interface PoseSample {
  epoch: number;
  capturedPerfMs: number;
  capturedMediaMs: number;
  tracking: TrackingQuality;
  pose: Pose;
}

export interface TrainingSnapshot {
  status: SessionStatus;
  pauseReason?: 'HAND_LOST' | 'USER' | 'MEDIA' | 'BACKGROUND';
  mediaMs: number;
  currentTaskIndex: number;
  currentPose: Pose;
  nextPose?: Pose;
  holdProgress: number;       // 0..1，仅供显示
  latestGrade?: { taskId: string; grade: Grade; nonce: number };
  confirmed: { completed: number; perfect: number; good: number; miss: number };
}

export interface SessionSummary {
  id: string;
  themeId: string;
  protocolId: string;
  manifestVersion: string;
  ruleVersion: string;
  status: 'COMPLETED' | 'ABORTED';
  plannedTasks: number;
  completedTasks: number;
  perfect: number;
  good: number;
  miss: number;
  judgedTasks: number;
  activeDurationMs: number;
  plannedDurationMs: number;
  startedAt: string;
  endedAt: string;
  syncState: 'LOCAL_ONLY' | 'PENDING' | 'SYNCED' | 'FAILED';
}
```

### 训练引擎接口

```ts
export interface TrainingEngine {
  prepare(input: { media: HTMLVideoElement; manifest: ThemeManifest }): Promise<void>;
  subscribe(listener: (snapshot: TrainingSnapshot) => void): () => void;
  start(): Promise<void>;
  pause(reason: 'USER'): void;
  resume(): Promise<void>;
  abort(): Promise<SessionSummary>;
  dispose(): void;
}
```

B 负责驱动媒体时间和结算，C 只调用命令并渲染快照。`latestGrade.nonce` 确保连续两个相同成绩也能各播放一次动画。组件卸载必须 `unsubscribe + dispose`，防止摄像头、RAF 或 Worker 泄漏。

### 识别准备接口

```ts
export interface RecognitionController {
  requestCamera(hand: 'LEFT' | 'RIGHT'): Promise<MediaStream>;
  subscribe(listener: (state: {
    tracking: TrackingQuality;
    pose: Pose;
    stableForMs: number;
  }) => void): () => void;
  startTutorialPose(pose: Exclude<Pose, 'UNKNOWN'>): void;
  finishTutorialPose(): void;
  stop(): void;
}
```

准备页用它完成权限和教学；训练引擎内部接同一识别源。错误统一返回业务 code，例如 `CAMERA_DENIED`、`MODEL_LOAD_FAILED`、`UNSUPPORTED_BROWSER`，页面不要解析底层错误字符串。

### 本机记录接口

```ts
export interface SessionRepository {
  save(summary: SessionSummary): Promise<void>;
  get(id: string): Promise<SessionSummary | null>;
  list(): Promise<SessionSummary[]>;
  watch(listener: () => void): () => void;
}
```

结果页先 `save` 成功再显示最终结果；云端上传是后续状态更新，不阻止本机打卡。页面不直接用 localStorage 保存正式记录。

## 6. 与 A 的素材合同

```ts
export interface ThemeManifest {
  id: string;
  title: string;
  protocolId: 'tendon-a-demo-v1';
  version: string;
  bpm: 60;
  videoUrl: string;
  posterUrl: string;
  durationMs: 90000;
  tasks: Array<{
    id: string;
    pose: 'STRAIGHT' | 'HOOK' | 'FIST';
    startMs: number;
    targetMs: number;
    endMs: number;
    holdMs: 3000;
  }>;
}
```

前端启动时校验：15 个任务、时间递增、范围不重叠、最后 `endMs=90000`、视频可播放。校验失败时不进入训练，显示“训练资源版本不匹配”。

视频含唯一音乐音轨，前端不另播背景音乐。A 不把 Perfect/Good/Miss、倒计时、中文动作说明烘焙进视频；这些由前端根据真实状态渲染。

## 8. 状态管理与渲染原则

把状态分为三类：

| 类型 | 放置位置 | 示例 |
| --- | --- | --- |
| 路由/表单 UI | React state | 当前准备步骤、邀请码输入、弹窗开关 |
| 训练业务状态 | `TrainingEngine` | 当前任务、成绩、保持、暂停原因 |
| 服务端缓存 | Query/service | 绑定信息、患者列表、云端训练记录 |

`PoseSample` 不进入 Context 或页面顶层 state。训练页订阅经过节流的 `TrainingSnapshot`，建议 UI 更新 10 Hz；视频和摄像头元素不因快照变化重建。判定动画以 `latestGrade.nonce` 触发，CSS 动画结束自行隐藏。

所有异步页面使用同一套四态：loading、content、empty、error。离线是页面级 banner，不把已有本机内容替换为空白错误页。

## 9. 媒体、摄像头和生命周期

- 情境视频使用 `playsInline`，不显示 controls，`preload="auto"`；播放由用户按钮触发并处理 `play()` 拒绝。
- 摄像头预览 `muted`、`playsInline`、镜像显示；离开准备/训练流程后停止所有 track。
- `visibilitychange`、`pagehide`、媒体 `waiting/stalled/error` 交给训练引擎暂停；页面只显示对应说明。
- 阻止应用内非法 seek：不提供进度控件；发现媒体时间跳变时暂停并要求恢复当前任务。
- 切换主题前释放旧 video、MediaStream、Worker 和 object URL；训练中阻止重复进入另一主题。
- 首次只加载封面和 manifest；进入准备页后加载所选模型与视频。展示前可为下一主题做轻量预取，但不能同时解码三个视频。

## 10. 页面错误文案

| 情况 | 标题 | 主操作 |
| --- | --- | --- |
| 摄像头被拒绝 | 需要摄像头才能识别动作 | 查看开启方法 / 重试 |
| 未检测到手 | 把一只手完整放入框内 | 自动继续，无按钮狂点 |
| 光线或距离不合适 | 调整光线或手机距离 | 重新检查 |
| 资源加载失败 | 训练内容没有加载完成 | 重试 |
| 网络中断 | 训练可继续，结果将先保存在本机 | 继续训练 |
| 上传失败 | 已保存在本机，治疗师暂时看不到 | 重新同步 |
| 微信能力受限 | 请在 Safari 或系统浏览器打开 | 一键复制链接 |
| 中途退出 | 本次不会计入打卡 | 继续训练 / 确认退出 |

医疗相关文案统一使用“体验”“训练任务”“动作完成”，不把游戏分数称为疗效、诊断或恢复程度。

## 11. 视觉与可访问性基线

视觉方向沿参考视频的轻松可爱风格，但操作层需要高对比、清楚和稳定。A 提供主色、辅助色、判定色和角色素材；C 将其集中到 `tokens.css`，三个主题只替换有限主题变量。

- 可点击区域至少 44×44 CSS px；暂停和退出不能重叠。
- 正文最小 14px，关键指令至少 18px；文字不能只靠颜色表达状态。
- Perfect/Good/Miss 同时显示文字、颜色和动效；关闭动画偏好时减少位移。
- 摄像头告知与分享确认使用可阅读正文，不用默认勾选代替同意。
- 竖屏遮挡、刘海和底部安全区使用 `env(safe-area-inset-*)`。
- 训练时避免页面滚动和双击缩放误触，但不要全局禁止用户在信息页缩放。

## 12. 开发适配器与禁止项

为了让 C 与 B 并行，可以实现 `MockTrainingEngine`，按固定时间发出状态用于页面开发。必须满足：

- 仅在 `import.meta.env.DEV` 且显式打开开发面板时可用。
- 页面固定显示“开发模拟数据”水印。
- 生产构建通过静态检查确保 mock 文件没有进入可访问路径；正式页面没有“模拟成功”按钮。
- UI 联调完成后，真实引擎实现同一接口，页面不改判分逻辑。

禁止项：在 React 组件里写手型阈值、从 `Date.now()` 推算媒体节奏、双音轨播放、每帧 setState、将云端上传成功当作本机打卡前提、用假数据展示为真实治疗师同步。

## 13. 前端实现顺序

### 第一个 3 小时

1. 初始化路由、tokens、AppShell 和错误边界。
2. 建 `contracts` 和 mock adapters，锁定与 B/A 的接口。
3. 做准备、训练、结果三个页面的手机骨架；用 12 秒样片验证叠加层。
4. 在一台 iPhone 和安卓检查 viewport、playsInline、按钮和安全区。

### P0

1. 接真实摄像头和准备步骤器。
2. 接真实 `TrainingEngine`，处理开始、暂停、恢复、退出和完成跳转。
3. 接本机 repository，完成结果和历史。
4. 检查发布环境禁用 mock；双平台完整走通。

### P1

1. 实现绑定预览与确认。
2. 实现同步状态与断网提示。
3. 实现治疗师登录、用户列表和详情。
4. 与 B 一起做权限和幂等手工测试。

### P2

1. 接入三个主题并做资源校验。
2. 加入微信回退、一键复制、空状态和视觉细节。
3. 完成二维码、现场引导和前两分钟体验彩排。

## 14. 前端验收

### 自动检查

- 路由可直接打开和刷新；未知主题进入安全错误页。
- manifest 校验拒绝错误任务数、错误时长和不递增时间点。
- 训练状态映射：丢手暂停、恢复倒数、退出确认、完成后打卡。
- 结果正确区分本机保存与云端同步；同步失败不删除记录。
